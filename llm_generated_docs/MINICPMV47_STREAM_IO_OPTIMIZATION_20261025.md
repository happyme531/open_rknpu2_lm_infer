2026-10-25。H88K 8GB，本地 GM7 SSD，pp512/tg128、物理 ubatch128、每层 40 个热槽。

所有正式配置的冷启动 pp 都读取 6498 条不同专家记录，10.380GB。40 个热槽的预热原来需要额外导入 1600 次。直接导入最终热槽后总导入降至 6498 次，省掉约 2.556GB 的记录导入流量；磁盘必要读取量不变。

双路读取提高了提前就绪率，也让更多无效预测在取消前完成。上表额外流量是完成读取字节减去真实冷需求字节，包含已读完后取消的记录。

直接入热槽后，热槽计算的位置仍影响 IO 重叠。逐组执行版本保持每个读取组的计算工作，不把预热专家全部积攒到层尾；这也是最终实现采用的时序。

## 保留的实现

- `store.rs`：页对齐读取缓冲区归还池中复用，最多保留 32 个空闲记录；每条仍是单一所有权。新增分配、复用和空闲内存统计。完整覆盖读取后才交付数据。
- `io.rs`：两个 worker 共用需求优先队列，每代已就绪与在途合计最多 32 条。相邻真实需求仍最多合并八条；取消和 reset 以 generation 归属，完成任务只移除自己持有的在途键。Trace 按 worker 区分线程。
- `paged.rs`：需要保留到 decode 的 prompt-tail 专家直接进入最终热槽，避免 cold→hot 的第二次导入；消费后及时归还读缓冲区。每个 token/rank 的贡献仍按原始顺序做 FP32 归约。

算子库、矩阵乘法和激活实现、量化权重、路由、缓存容量及替换策略没有修改。实验中的专家分组顺序用于调整加载重叠。

## 校验与内存边界

每个成功样本都比较完整 tg128 FP32 logits，与既有常驻基线逐字节一致。板端 11 项专家存储、队列、取消、reset 和窗口测试通过；release clippy 与格式检查结果随构建日志保存。

正式计时样本不记录 trace，也不设置 trace 的 malloc 环境变量。独立 trace 使用 `MALLOC_MMAP_THRESHOLD_=131072`，只分析顺序、槽位、重叠和重复读取，不混入速度均值。

全部正式样本的最小 MemAvailable 和系统换页保留在原始 telemetry/case 中。部分较早消融样本没有匹配到改名后测速进程的 VmSwap：全系统 swapout=0 的样本可确认该阶段没有新增换出；双 worker 一次样本全系统换出一页，无法归属。最终逐组版本及后续 trace 使用了匹配可执行文件名称的进程采样，VmSwap 以这些直接采样为准。

当前连接仍存在已知可纠正 PCIe 错误，本轮保持 PCIe、内核和挂载配置不变。频率固定 CPU4–7 2.4GHz、NPU mask7 1GHz、DDR2112MHz，每次运行通过原 harness 还原。没有装入完整路由专家权重。
