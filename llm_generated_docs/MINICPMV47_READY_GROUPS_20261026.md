# MiniCPM-V 4.7：冷专家分组与读取重叠实验

8 GiB H88K 上保留约两组冷专家的调度：pp512/tg128、DSpark draft=3 下，配对 decode 均值 **7.707 → 7.934 tok/s（+2.95%）**，目标验证总耗时 **13.874 → 13.331 s**。prefill 策略保持原样。

## 调度与上游对应关系

OpenBMB/llama.cpp-omni 的 main `a64932ec615e1463158129feaf2f0752d0c07a2e` 包含可选的 MoE 两段执行：按每个 token 的 top-k 排名拆分，前段计算与后段缺失专家读取重叠，随后拼回原排名、整体加权归约。`LLAMA_MOE_MATMUL_SPLIT` 未设置时默认 0；该路径受 decode 阶段及 bias/scale/合并权重条件约束。

- [上游图构建与原顺序归约](https://github.com/OpenBMB/llama.cpp-omni/blob/a64932ec615e1463158129feaf2f0752d0c07a2e/src/llama-graph.cpp#L1641-L1706)
- [缺失专家延后读取](https://github.com/OpenBMB/llama.cpp-omni/blob/a64932ec615e1463158129feaf2f0752d0c07a2e/src/llama-moe-slot.cpp#L2740-L2780)

本实现沿用相同的计算与加载重叠思路，按 record 就绪状态组成冷组。已有热专家先执行；冷组先等待至少 `max(3, ceil(min(冷专家数, 缓存槽数)/2))` 个专家（剩余不足时全部取完），再领取其余已发布的 ready 记录，随后立即执行。未 ready 的读取和后台导入继续运行。专家并集能放入缓存时，冷执行最多两组；超过缓存容量时继续分组，始终固定当前组的槽位。

`Reader::try_take_any` 仅领取已发布记录，不接管排队中的后台导入。各组结果仍写回原 token/rank 对应位置，最终按原 FP32 FMA 顺序归约。prefill 的文件顺序分组、缓存容量、预测器、I/O 线程数及算子实现均保持原样。

## Trace：重叠收益与调用代价

以下来自独立的3次诊断 trace，默认分配器、相同负载。累计时间除以128个输出；专家算子是 `bank.run` 完整调用，包含其内部 CPU 工作和同步，不能解释为纯硬件执行时间。

| 每个输出 token / 整段次数 | 基线 | 小组 | 约两组 |
|---|---:|---:|---:|
| Record领取/等待 ms | 30.583 | 23.132 | 26.407 |
| 主线程导入 ms | 6.733 | 4.327 | 5.073 |
| 专家算子完整调用 ms | 28.898 | 36.293 | 31.221 |
| 其他paging工作 ms | 5.398 | 6.965 | 6.120 |
| Routed总计 ms | 71.612 | 70.716 | 68.821 |
| 专家算子调用总次数 | 2790 | 5461 | 3915 |
| 实际读取 MB/token | 199.243 | 196.860 | 197.221 |
| 必需冷专家 MB/token | 161.316 | 161.316 | 161.316 |
| 读取量/验证窗口 GB/s | 1.433 | 1.423 | 1.451 |

两组策略将 routed 时间从71.612降至68.821 ms/token：record等待约省4.18 ms，主线程导入约省1.66 ms，额外完整算子调用增加约2.32 ms，其余paging增加约0.72 ms。单纯继续缩小组会扩大完整调用成本：小组版已有5461次调用。

两组策略的后台导入与专家计算重叠由1.456增至1.952 s；读取与专家计算重叠由3.631增至3.942 s。必要冷专家仍是12926条/128 token；收益来自时序重叠。实际读取还含无用的预测数据。读取量/窗口是端到端有效速率，不能用作SSD峰值；两组 trace 中至少一个pread活跃的联合区间为12.854 s，整个验证窗口约17.395 s。

3份trace的全部1440次路由和1365次LES预测一致。Decode包含1400次逐层路由、44480次token/expert分配，缓存分配命中65.45%，唯一专家命中56.60%。LES覆盖8526/12926个冷需求（65.96%）。以下分母均为12926个冷需求。

## 适用范围

每档两轮正式样本、单一固定提示词；约3%的收益适用于当前缓存容量、SSD链路及冻结算子快照。两种分组的收益差不足以确定普遍最优粒度。进程VmSwap峰值含加载和析构阶段，不能直接当作decode的swap I/O；阶段采样见 `memory_summary.json`。当前主线等待仍以pread为主，继续增加细粒度提交的收益受完整算子调用成本限制。
